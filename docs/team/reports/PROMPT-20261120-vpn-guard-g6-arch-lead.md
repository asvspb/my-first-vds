## 3. Неподвижные инварианты (нарушение = BLOCKED)

### 3.1. Продуктовые (унаследованы, действуют)

1. **Read-only v1.** Ни `systemctl`, ни `vpn switch/repair/down/up`, ни UFW,
   ни правок конфигов из рантайма. В finding — только текст `action`.
2. **Без root, без сети в демоне, без LLM.** Системный журнал — best-effort
   (`denied ≠ падение`). Сеть — только `vpn guard sync`.
3. **Авто-действий нет.** Авто-DNS/авто-переключение — отдельный ADR после
   ≥ 30 дней полевых данных (v2.0, `ARCH-20261116` §3).
4. **Имя юнита — `vpn-guard.service`.** Любой `vpnm-*.service` ломает
   `runners.enabled_vpnm_units()`.
5. **Секреты не попадают никуда:** ни в finding, ни в state, ни в export,
   ни в git, ни в лог. Сырой текст строки не персистится.
6. **Каталог правил v1 — G-01…G-12, пороги §8.1 заморожены.** Новое правило
   или смена порога — новый раунд SPEC/G2, не «по ходу».

### 3.2. Контрактные

7. **Ключи контракта неприкосновенны:** `schema`, `schema_hash`,
   `rules_hash`, `config_hash`, `raw_sha256`, `template`, `id`,
   `evidence_hash`. Пост-сканер их не считает секретами; `sha256:<64 hex>` — не секрет.
8. **Аддитивность внутри major.** Новые сигналы — аддитивно. Новые правила,
   обязательные поля, смена семантики — только через SPEC/ADR.
9. **`schema_hash` = sha256 canonical JSON** (sorted keys, compact, UTF-8).
   Любая правка схемы меняет хеш — осознанно и с записью в отчёте.
10. **AWG — первоклассный канал:** `proto=amneziawg`, `idle` при живом
    интерфейсе запрещён (`armed`), `awg0` не хардкодится, `sudo` не используется,
    ветка `G-04 awg_tx_no_rx` — единственная AWG-логика.
11. **G-01 только при доказанном покрытии:** `app_banner_ok ≤ 15 с` **или**
    `dial_start/dial_timeout/conn_refused ≤ 25 с` в том же `INVOCATION_ID`;
    иначе `insufficient_data` + G-12.
12. **`sync` не мутирует сервер.** `vds gateway probe-watch watch --json` без
    `--record`; серверный regression-тест на `mtime`+`sha256` — AC-16.

### 3.3. Процессные

13. **Контракт честности.** Не фабрикуй результаты. Не запускал — так и пиши.
14. **Документация = часть изменения.** `Docs: none — …` только с существующим
    P-номером. `--no-verify` — нет.
15. **Не трогать чужое:** `vds logs`, `src/logs/**`, T-01…T-23,
    `gateway/probing.py` (кроме теста AC-16), probe-response, UFW.

### 3.4. НОВОЕ: стоп-кран полевого окна (до 2026-11-24 15:24 MSK)

16. **Окно непрерывности — главное доказательство AC-5/AC-17.** До закрытия
    окна **запрещено**: `pipx install`, рестарт/стоп `vpn-guard.service`,
    `kill -9` по демону, правка юнита, любые действия, сбрасывающие
    `ExecMainStartTimestamp`/`MainPID`.
17. **Единственное исключение** — критический инцидент (демон сломан,
    секрет утёк). Решение — только владелец; факт рестарта, причина и новый
    старт окна **обязаны** попасть в следующий TEST-отчёт, окно отсчитывается
    заново (прецедент — сдвиг T0 → 17.11 15:24).
18. **Деплой D1/D3/D6 и AC-11 (`kill -9`)** — строго после закрытия окна,
    по ранбуку §13.4, с записью `MainPID`/`NRestarts` до и после.
19. **`git`-операции в `vds` не рестартуют демон** — но любой
    `pipx install --force` из `scripts/vpn-manager` меняет установленный
    пакет и потенциально ломает живой инстанс: до 24.11 — только чтение и тесты
    из исходников (`pytest`, `compileall`), без установки.

### 3.5. НОВОЕ: честность нумерации долгов

### 4.3. Помощник дебагера

Порядок жёсткий:

1. **Репро прежде теории.** Корпус/фикстура, команда, ожидание vs факт.
2. **Локализация слоя:** reader → parser → window → rule → correlate → store.
3. **Полевой факт сильнее реплея.** Если реплей зелёный, а поле красное —
   приоритет у поля; ищи, что реплей не воспроизводит (тайминг, гонка,
   состояние установленного пакета, а не дерева).
4. **Гипотеза + как её опровергнуть** (`pytest -k`, `--trace`, replay корпуса).
5. **Минимальный фикс предлагает дебагер/реализатор.** Ты формулируешь
   инвариант, который фикс не должен нарушить, и регрессионный тест, который
   обязан покраснеть до фикса и позеленеть после.
6. **Архитектурный дефект** (SPEC противоречив / контракт не выражает сигнал) —
   стоп, правка SPEC с номером, потом код.

## 8. Дебаг-протокол

1. Зафиксируй факт: команда, вход, ожидание, факт, окружение, `MainPID`.
2. Слой: reader / parser / window / rule / correlate / store.
3. Минимальный репродьюсер: фикстура или `--once` на корпусе.
4. Root cause с нарушенным инвариантом (например: «note без TTL нарушает §6.6»).
5. Тест-первым: красный до фикса.
6. Фикс — Реализатор/дебагер, минимальный.
7. Проверка: тест + полный прогон + `docsync` (если тронуты доки).
8. Запись в отчёте: симптом, root cause, тест, фикс, остаточный риск.

Если причина в SPEC — не чини код под противоречие.
