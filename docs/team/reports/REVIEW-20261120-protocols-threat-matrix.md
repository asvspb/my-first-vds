# REVIEW — зачем оркестратору столько протоколов: матрица «угроза → транспорт» (2026-11-20/21)

- **Источник:** разбор внешнего архитектора-LLM (Gemini, app-architect) на вопрос
  владельца «зачем приложению столько протоколов?»; зафиксирован по запросу
  владельца («задокументируй информацию»).
- **Основание источника:** README.md, docs/VPN-PROTOCOLS.md,
  docs/CENSORSHIP-ROADMAP.md, docs/CENSORSHIP-PATTERNS.md,
  [REVIEW-20261120-resilience-roadmap](REVIEW-20261120-resilience-roadmap.md)
  (репозиторий `asvspb/my-first-vds`, ветка main).
- **Связано:** [VPN-PROTOCOLS](../../VPN-PROTOCOLS.md),
  [CENSORSHIP-ROADMAP](../../CENSORSHIP-ROADMAP.md) §1.4/§3,
  [ADR-016](../../adr/ADR-016-p2p-link-multi-carrier.md).

## Короткий ответ

Против ТСПУ нет одного «вечного» протокола, а блокировки бьют по разным слоям
сети **по отдельности**. Набор транспортов в репозитории набран не «про запас»,
а по принципу defense in depth — так, чтобы у них были **непересекающиеся
точки отказа**.

## 1. Какую конкретную угрозу закрывает каждый транспорт

| Угроза / сбой | Что умирает | Что остаётся живым и почему |
|---|---|---|
| Блокировка или жёсткий троттлинг UDP целиком | Hysteria2, AmneziaWG | **VLESS + Reality** (TCP 443) — работает поверх TCP, мимикрирует под TLS 1.3 к белому сайту; при активном зондировании сервер прозрачно перенаправляет сканер на `dest`. |
| Троттлинг TCP 443 / детект TLS-фингерпринта Reality (часто на мобильных сетях) | Reality (TCP) | **Hysteria2** (UDP 443, QUIC) — другой L4-протокол, лучше переносит потери пакетов на Wi-Fi/LTE; при сканировании отдаёт decoy-маску (masquerade). |
| Детект/резка «голого» QUIC | обычный Hysteria2 | **Hysteria2 + obfs** (Salamander) — маскирует QUIC-заголовки; плюс port hopping против троттлинга по конкретному порту. |
| Деградация прокси-движков (Xray / QUIC) + нужен L3-туннель для системного split | Reality, Hysteria2 | **AmneziaWG** (UDP 51825) — независимое ядро (обфусцированный WireGuard с мусорными пакетами до хендшейка и без дефолтного keepalive-маяка). Удобно ложится в системный доменный split на десктопе. |
| Полный блок IP сервера (TCP + UDP + ICMP мертвы одновременно) | все прямые протоколы на этом IP | **VLESS + WS + TLS за CDN** (origin TCP 2053) — клиент подключается к edge-узлам CDN, не светя IP exit-сервера. Сейчас в статусе холодного резерва (origin снят) из-за высокой задержки на бесплатном CF — решение Q6. |
| TCP-резерв без Reality | Reality | **VLESS XHTTP** (TCP 8443 / Xray fallback) — HTTP-мимикрия с рандомизацией padding против ML/SPLT-анализа. В коде есть; полевой статус — см. примечание оркестратора ниже. |
| Удар по межузловой ноге RU-relay ↔ exit (резка UDP между серверами) | UDP-магистраль (AWG) | **Второй носитель поверх TCP/TLS/WSS** (wstunnel / `wg-ws0` на 9443) — снимает SPOF магистрали (ADR-016, [REVIEW-20261120-resilience-roadmap](REVIEW-20261120-resilience-roadmap.md)). |

## 2. Почему список в репозитории кажется ещё длиннее

В README рядом с антицензурным gateway лежат `zerotier`, классический `wireguard`
и `coturn` (TURN для WebRTC) — это **не часть антицензурных эшелонов**:

- классический WireGuard в [VPN-PROTOCOLS](../../VPN-PROTOCOLS.md) прямо отнесён
  к «мёртвому для РКН» (детектируется за секунды);
- ZeroTier и Coturn решают отдельные инфраструктурные/сетевые задачи, а не обход
  ТСПУ.

## 3. Архитектурный баланс (почему не 15 протоколов)

Каждый дополнительный транспорт — не «бесплатная страховка», а цена
сопровождения:

- отдельные порты, правила firewall и ACME-хуки сертификатов (уже были инциденты
  расхождения `cert_domain` / `sni`);
- сложнее мониторинг, диагностика и ручное/будущее автоматическое переключение
  на клиенте.

Поэтому в [CENSORSHIP-ROADMAP](../../CENSORSHIP-ROADMAP.md) §3 зафиксирован
осознанный потолок: NaiveProxy, TUIC v5 и Snowflake/WebRTC в текущий скоуп
(W1–W6) не берутся; упор сделан на связку из **разнородных по L4/ядру** базовых
транспортов (Reality + Hysteria2(+obfs) + AWG) и **наблюдаемость**
(probe-watch + vpn guard), чтобы различать локальный сбой, блокировку протокола
и блокировку IP.

## 4. Примечания оркестратора (сверка с фактами сессии 2026-11-20)

- **XHTTP-строка таблицы:** у источника «в поле сейчас снят (нестандартный порт
  8443 притягивал DPI-давление, ограниченная поддержка клиентов)». Проверка по
  read-only фактам 2026-11-20 ([SPEC-20261120-p2p-link](../specs/SPEC-20261120-p2p-link-multi-carrier.md)
  §1): на asv2 `8443/tcp` **занят xray — XHTTP-инбаунд жив**. «Снят» относится
  к клиентским split-схемам/старым узлам, а не к серверному инбаунду asv2 —
  статусы уточнить при следующей ревизии VPN-PROTOCOLS.
- **Q6:** у источника «вопрос Q6 открыт»; фактически Q6 **закрыт решением**
  (`f5794ce`, DECISION Q6): `:2053` — 🧊 холодный резерв, код не удалять, на asv2
  не поднимать. Суть (холодный резерв) у источника передана верно.
- Порты obfs-инстанса и hop-диапазона (20000–20500) в таблице источника —
  концептуальные; фактические значения берутся из state узлов (UFW harden
  нормализует hop-диапазон из state).
