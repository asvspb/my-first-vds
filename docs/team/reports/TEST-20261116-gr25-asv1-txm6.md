> **Тип:** TEST-отчёт (живая приёмка, snapshot).
> **Дата:** 2026-11-16 ~19:23–19:40 UTC. **asv1:** 45.91.168.58 (SSH 22).
> **Код:** сервер `my-first-vds` `43d1ee6` (GR-25 + миграция + `--skip-domain-check`),
> клиент `ubuntuInstaller` `1807945` (padding/xmux, Xray 26.1.23).
> **Секреты:** path/UUID/ключи в отчёт не попадают; только хэши и счётчики.

```
config_sha     = 3ed36803…
```

Бэкап: `/root/vds-pre-gr25-20261116-1923.tgz` (327K: `/opt/my-vds` без venv,
`/var/lib/vds`, `config.json`, unit-файлы).

## 2. Миграция

`vds xray add-transport xhttp --domain 103-45-247-172.eu-cloud-xip.com --mode
port --apply --yes --skip-domain-check`

`--skip-domain-check` потребовался потому, что IP узла сменился на
45.91.168.58, а A-запись старого домена ещё указывает на 103.45.247.172.
Сертификат и SNI остаются прежними (домен тот же); проверка E1 иначе
блокировала бы миграцию.

После apply:

```
xhttp_keys        = [["mode","path","xPaddingBytes"]]
xhttp_path_sha    = 4d6278b5…    # НЕ изменился (ссылки не сломаны)
ws_sha            = d42fe6de…    # CDN 2053 байт-в-байт
reality_sha       = 895f65ea…    # Reality 443 не изменился
ws_ports          = [2053]
clients           = 443:1, 8443:1, 2053:1
vds-xray.service  = active; xray -test = OK
listen            = 443, 8443, 2053
```

CDN-клиент `laptop` и XHTTP-клиент `xhttp-web` сохранены.

Xray **26.1.23**, socks 127.0.0.1:2099, вне системного split (xmux — свойство

## 4. Остаток / риски

1. **DNS старого домена** `103-45-247-172.eu-cloud-xip.com` всё ещё указывает
   на 103.45.247.172 (мёртвый IP). Обычные клиенты по старым ссылкам не
   подключатся, пока A-запись не переключена на 45.91.168.58. T-XM6 прошёл
   через явную подмену адреса на IP при прежнем SNI.
2. `45-91-168-58.eu-cloud-xip.com` уже резолвится в новый IP, но LE-сертификата
   на него нет; для штатных ссылок нужен либо DNS-переезд старого домена, либо
   выпуск сертификата на новый домен и перевыпуск XHTTP-ссылок.
3. XHTTP-путь остался старым (`/xhttp`), т.к. миграция сохраняет path.
   После стабилизации DNS рекомендуется `--regenerate-path` + `vpn profile pull`
   (HF-2-гигиена; текущий UUID фигурировал в диагностике).
4. `--skip-domain-check` — только для миграции после смены IP; в обычном
   деплое E1 должен оставаться включённым.
