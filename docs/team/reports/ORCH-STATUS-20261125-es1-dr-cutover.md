## 3. Открытый дефект для WP-QX-3 (клиент, ubuntuInstaller) — нужен вердикт

**`vpn start relay` не идемпотентен**: повторный прогон поверх живого контура
дал «полу-применённый захват» (mode=RELAY, default-маршрут выпал в main →
трафик мимо туннеля; клиент видел «то Таллинн, то провайдер»). Просьба
дополнить WP-QX-3: (а) подъём = down→up или пост-проверка таблиц
(fwmark/table/default-dev) с failure при расхождении; (б) «запущен»
рапортовать только при зелёном data-plane; (в) дефолт `relay` + fail-closed
direct (уже в SPEC §4). До этого клиентский контур владельцем осознанно
оставлен в DIRECT (безопасное состояние).
