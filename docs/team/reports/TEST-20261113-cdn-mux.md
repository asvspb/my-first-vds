## 3. Функциональная проверка mux (ключевой результат)

Серийно, паузы 2 с (И26), один и тот же момент времени, `example.com`:

| Режим | Запросы | Успех | TTFB |
|---|---|---|---|
| контроль: прямой TLS к CF (`asvpersonal.ru`) | 3 | 3/3 | 0.57 / 0.52 / 0.73 с |
| `cdn-home` **без mux** | 5 | **5/5** | 2.53 / 2.39 / 2.40 / 2.48 / 2.37 с |
| `cdn-home` **mux** (`concurrency: 8`) | 5 | **1/5** | 3.13 с; остальные `code=000`, timeout 15 с |
| mux `concurrency: 1` (ручной конфиг) | 5 | 3/5 | 2.39 / 4.07 / 1.04 с; 2× `000` |
| mux `concurrency: 2` (ручной конфиг) | 5 | 2/5 | 3.07 / 1.14 с; 3× `000` |

Логи клиента: предупреждения Xray про deprecated WS/Host, ошибок mux нет;
первый запрос проходит, затем соединение «залипает» (curl timeout).

**Вывод:** это **не TSPU-окно**: в том же прогоне nomux 5/5 и прямой TLS к CF
3/3, а mux стабильно ломается на 2–4 из 5 запросов. Проблема в связке
`Mux.Cool + WebSocket + Cloudflare` (или в серверной поддержке mux на этом
инбаунде), а не в канале. Смена `concurrency` не лечит.

## 4. Замечания к WP-3

1. Бенчмарк не делает **контроль** (прямой TLS к CF) — из-за этого фейлы mux
   были списаны на «TSPU-окно».
2. Нет smoke-проверки после `vpn up`: если режим нерабочий, скрипт всё равно
   гонит 7×30 с таймаутов (14 минут) — нужен быстрый `curl` и early-fail или
   пометка режима.
3. `trap` снимает только профиль; `vpn reset` в конце есть — ок.
4. Перцентили/исключение фейлов реализованы корректно.

## 5. Решение по WP-1 (варианты)

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Откатить mux-фичу** (revert `a5075a0`), оставить WP-2/3 | не тащим нерабочий тумблер; меньше кода | теряем «одно соединение» идею |
| **B. Оставить, но пометить experimental + скрыть из help** | код есть для будущего | пользователь может включить и получить «мёртвый» канал; противоречит «не тащим сломанное» |
| C. Переделать на XHTTP-through-CF (новая SPEC) | реальное мультиплексирование, без Mux.Cool | серверный инбаунд + CF, отдельный цикл |

**Рекомендация:** **A** сейчас (откат mux), **C** — отдельной SPEC
`cdn-xhttp-cf` (там же Argo/tunnel при необходимости). WP-2/WP-3 оставить.
