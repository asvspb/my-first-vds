# REQ-20261114-ru-relay — RU-relay: входной релей на российском VDS (Фаза 1 + реализация v1)

  прямое указание владельца 2026-11-15: «жду код для релея; развертывание

- **Автор:** техлид+кодер (vds-coder), оформление по конвенциям
  [REQ-20261112](REQ-20261112-transport-hardening.md)
- **Дата:** 2026-11-15

- **Закрывает векторы:** mobile whitelist (W-soft), IP-троттлинг (смена src-пути),
  полный блок IP exit (ноутбук вообще не касается asv1) — см. CENSORSHIP-PATTERNS §3a/§3.

## 1. Проблема

Последний непокрытый вектор модели угроз — **mobile whitelist** (режим
оператора «только RU-ресурсы», PATTERNS §2.11): иностранный dst-IP блокируется
на уровне оператора, мёртвы все каналы с foreign входной точкой (socks-профили,
CDN). Плюс накопленный болевой опыт: троттлинг/баны exit-IP asv1 лечатся
сейчас только переездом (MIGRATE-VDS), ротация exit-IP дорогая. RU-relay
закрывает оба: вход domestic (RU-IP пропускается whitelist-режимом), выход
декоммутируется от конкретного asv1 (смена ноги — правка relay-конфига,
клиенты не трогаются).

## 2. Скоуп v1 (зафиксирован, НЕ расширять)

- **Релей** = RU VDS: KVM, Москва/СПб (RTT 10–20 мс от Волгограда), 150–300₽/мес.
  Критерии закупки (Фаза 0): dual-stack IPv6 обязательно, UDP без шейпинга,
  дешёвая смена IP, чистота /24 до годовой оплаты (факты: И22 — белые списки
  «перо оператора + перо /24»).
- **На релее:** AWG-сервер **UDP 443** (ОДНА серверная инстанция) +
  **Xray Reality TCP 443 RU-SNI** (фолбэк; тот же номер порта, другой L4) + UFW.
- **Топология:** `awg0` (сервер, подсеть **10.10.0.0/24** — НЕ 10.9.0.0/24,
  которая занята asv1-ногой) + отдельная awg-клиентская нога `awg1` до asv1
  `103.45.247.172:51825` (конфиг от `vds amneziawg add-client relay` на asv1,
  на релее wg-quick-стилем второй интерфейс; **v4-only — у asv1 нет IPv6**).
- **Policy-routing:** RU-CIDR (ipdeny/RU-агрегат) → direct eth0; остальное →
  awg1 до asv1; MASQUERADE на awg1 (+ eth0 для RU-direct из awg0-подсети);
  nftables set + **недельный** systemd-таймер обновления RU-CIDR,
  идемпотентно.
- **DNS-политика релея (отдельный пункт):** заблокированные домены НЕ через
  RU-резолверы; v1 — предложить dnsmasq-схему (RU→direct, остальное→форвард
  через awg1) рендером конфига + раздел в ранбуке (исполнение — OQ-3).
- **MTU/MSS двойной инкапсуляции:** MTU awg0 = **1280** (зафиксировано);
  awg1 MTU дефолт (1420) — там одиночная инкапсуляция.
- **Клиенты:** ноутбук — инстанция `vpn-awg-split@relay` в ubuntuInstaller
  (доменный split без изменений); телефон — пир на релее, endpoint
  `relay.asvpersonal.ru:443`, DNS уходит на релей.
- **Домен:** `asvpersonal.ru` УЖЕ есть → только A-запись `relay` в
  DNS-only/сером облаке (**CF-прокси не пропускает UDP и не-HTTP TCP**) —
  обязательный пункт приёмки Фазы 0.
- **Приёмка Фазы 0 (gate):** leg smoke-test ДО развёртывания — с голого RU VDS
  UDP-handshake до asv1:51825 (врем. пир на asv1 → awg-клиент на RU VDS →
  handshake → удалить пир); стоп + эскалация владельцу, если нога
  мертва/шейпится.
- **CLI (`vds relay`):** init (dry-run по умолчанию, `--apply`), status,
  add-client; каждая команда — полный человекочитаемый `--help` с примерами
  (прямое требование владельца). CLI повторяет шаги ручного ранбука 1:1.
- **Ранбук:** docs/DEPLOY-RU-RELAY.md — пошаговый copy-paste runbook руками
  по ssh (Фаза 2), каждый шаг с проверкой.

## 3. Non-goals v1

- W-strict-обход (только матрица полевой проверки — ADR-007 §Whitelist/Test-plan).
- Второй релей, v6-нога relay→exit, L7-цепочка xray→xray, мульти-инстанс
  AWG-сервера, реализация dnsmasq-схемы (только предложение), Hysteria2 на
  релее, автовыбор профиля (vpnm-автодетект — кандидат-WP отдельно).

## 4. Функциональные требования

- **FR-1** `vds relay init --exit <asv1-ip> --domain relay.asvpersonal.ru
  --sni <RU-сайт>` — dry-run по умолчанию (план без мутаций), `--apply` —
  исполнение; preflight: порты 443 TCP/UDP свободны (`ss` через
  core.netcheck), DNS-резолв relay-домена → публичный IP этого сервера,
  ip_forward; ключи/конфиги атомарно 0600.
- **FR-2** init ставит: AWG-сервер UDP 443 (подсеть 10.10.0.0/24, iface awg0,
  переиспользование рендеров src/amneziawg/config.py и юнит-шаблона
  vds-amneziawg.service.tpl), Reality TCP 443 с данным SNI (переиспользование
  src/xray/install.py), awg1-ногу до asv1 (конфиг `--exit-conf` или шаблон
  «перенести с asv1»), UFW-правила (443/udp, 443/tcp), ip_forward,
  nftables RU-CIDR set + недельный таймер, MASQUERADE awg1/eth0, MTU awg0=1280.
- **FR-3** `vds relay status` — инстансы/юниты, маршруты (nft list), живость
  ноги до asv1 (handshake-возраст из `awg show`), сводка.
- **FR-4** `vds relay add-client <имя>` — генерация пира awg0 (endpoint
  relay-домена:443), .conf 0600, без секретов в stdout по умолчанию.
- **FR-5** Регистрация в src/main.py — ленивые импорты внутри команд.
- **FR-6** systemd-шаблоны relay-юнитов в systemd/ (не хардкодить пути).
- **FR-7** Деструктивные/мутирующие операции: dry-run по умолчанию +
  --apply; FileLock; идемпотентность (повторный init — дотягивает, не ломает).
- **FR-8** (харднинг, находки AWG-Router habr 1107904, WP-6): (a) fail-safe
  «unreachable default» в таблице выхода — при падении ноги relay→asv1
  не-RU-трафик не уходит с RU-IP напрямую; (b) MSS-clamp в обе стороны
  (страховка двойной инкапсуляции помимо MTU 1280); (c) DNS-запросы клиентов
  через путь выхода (SO_MARK), без тихого отката на открытый RU-резолвер;
  (d) I1-маски AWG — вне v1, OQ-5 SPEC.

## 5. Acceptance criteria

- **AC-1** `python -m compileall -q src` exit 0; `pytest -q` exit 0 (в т.ч.
  tests/relay/); числа в отчёте.
- **AC-2** `vds relay init --help` / `status --help` / `add-client --help` —
  человекочитаемы с примерами; `vds relay init` без --apply не мутирует
  (печатает план).
- **AC-3** Unit-тесты покрывают: генераторы конфигов (сервер/клиент/dnsmasq),
  dry-run-план, nft-правила, CIDR-агрегацию, статус-парсинг, аллокацию пиров
  10.10.0.x.
- **AC-4** Секреты не в stdout/логах/git; конфиги 0600 атомарно.
- **AC-5** (полевая, Фаза 0/2 — ранбук) leg smoke-test; `curl --interface
  awg1 ifconfig.me` = IP asv1; ya.ru идёт мимо awg1 (tcpdump/mtr); reboot-тест
  — юниты поднимаются, правило fwmark/таблица восстановлены.
- **AC-6** (полевая, WP-6) fail-safe: при остановке awg1 не-RU-трафик с релея
  НЕ уходит в интернет с RU-IP (проверка в ранбуке); MSS-clamp виден в
  nft-листе; unit-тесты рендеров clamp/unreachable зелёные.
