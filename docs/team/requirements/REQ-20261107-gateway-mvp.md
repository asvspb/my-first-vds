## 1. Контекст

`vds` сегодня — набор отдельных VPN-команд (ZeroTier/ZTNET, WireGuard, Coturn) без
протоколов, устойчивых к DPI. Roadmap превращает его в self-hosted платформу обхода
блокировок. Утверждён MVP-скоуп — фазы 0–2:

- **Фаза 0:** tech-debt P1–P3 + core-примитивы (`core/protocol.py`,
  `core/netcheck.py`, `core/secrets.py`, `core/units.py`, `gateway/store.py`)
  + тесты store.
- **Фаза 1:** Xray + VLESS Reality (TCP 443), CLI `vds xray install|add-client|status|remove`,
  share-link, юнит-тест рендера конфига.
- **Фаза 2:** Hysteria2 (UDP 443) **без домена**: self-signed сертификат +
  `insecure=true` у клиента (тестовый режим), masquerade-decoy, sysctl BBR/буферы,
  CLI + TUI.

Ключевое ограничение приёмки: протоколы нельзя полноценно проверить локально —
AC разделены на **[локально]** (pytest, без root/сети) и **[VDS]** (живой сервер,
частичная проверка).

## 2. Пользователи и сценарии

| Роль | Сценарий | Частота |
|---|---|---|
| Оператор VDS (владелец сервера) | Устанавливает Xray Reality и/или Hysteria2 на чистый Ubuntu 24.04 | редко (1 раз на сервер) |
| Оператор VDS | Добавляет/удаляет клиентов, выдаёт share-link | регулярно |
| Оператор VDS | Смотрит статус юнитов/портов/сертификатов | регулярно |
| VPN-клиент (v2rayNG, NekoRay, Hiddify, sing-box) | Импортирует share-link и подключается | на каждого клиента |
| Разработчик (`vds-coder`/`vds-tester`) | Запускает `pytest -q` локально без root/docker/сети | каждый прогон |

## 3. Функциональные требования

Маркировка AC: **[локально]** — проверяется pytest/командой без root; **[VDS]** —
только на живом сервере (частичная приёмка владельцем по чеклисту).

### Фаза 0 — фундамент

#### FR-0.1. Единый `load_env` (TECHDEBT P1)
**User story:** Как разработчик, я хочу одну функцию `load_env` в core, чтобы правки
не расходились между копиями.
**AC:**
- **Given** репозиторий после рефакторинга
- **When** `grep -rn "def load_env" src/`
- **Then** найдена ровно одна функция **[локально]**
- **Given** `watchdog.py`, `reconcile.py`, `nat.py` импортируют `load_env`
- **When** `python -m compileall -q src`
- **Then** exit 0, поведение загрузки env не изменилось **[локально]**

#### FR-0.2. Синхронизация версий зависимостей (TECHDEBT P2)
**User story:** Как оператор, я хочу одно место задания версий, чтобы `install.sh`
и `pip install -e .` ставили одно и то же.
**AC:**
- **Given** приведённые `pyproject.toml` и `requirements.txt`
- **When** `pip install -e .` и `pip install -r requirements.txt` в чистом venv
- **Then** результирующие версии typer/pydantic/rich/questionary/requests совпадают **[локально]**

#### FR-0.3. Безопасный `docker_exec` (TECHDEBT P3)
**User story:** Как разработчик, я хочу `docker_exec(container, ["cmd", "arg"])`
со списком аргументов, чтобы аргументы с пробелами/кавычками не ломались.
**AC:**
- **Given** новый код `src/`
- **When** `grep -rn "docker_exec" src/`
- **Then** все вызовы передают список (строка допустима только как legacy-параметр,
  парсится через `shlex.split`) **[локально]**
- **Given** кодированный прогон на машине с ZTNET-контейнером
- **When** `docker_exec(CONTAINER, ["zerotier-cli", "-j", "listnetworks"])`
- **Then** команда выполняется корректно (smoke) **[VDS]**

#### FR-0.4. `core/netcheck.py`
**User story:** Как оператор, я хочу проверку занятости порта и public IP перед
установкой сервиса, чтобы установка не ломала существующие сервисы.
**AC (интерфейс — требование к поведению, реализация/моки — на SPEC):**
- **Given** порт занят (мок `ss`)
- **When** `port_free(port, "tcp")`
- **Then** возвращает False, исключения нет **[локально]**
- **Given** свободный порт
- **When** `port_free(port, "udp")`
- **Then** возвращает True **[локально]**
- **Given** утилита недоступна / нестандартный вывод (мок)
- **When** вызов `port_free`
- **Then** ошибка возвращается значением/ShellResult, не необработанным исключением **[локально]**

#### FR-0.5. `core/secrets.py`
**User story:** Как оператор, я хочу генерацию UUID/паролей/ключей с атомарной
записью в файл 0600, чтобы секреты не утекали и не повреждались при обрыве.
**AC:**
- **Given** генерация секрета и запись в файл
- **When** файл создан
- **Then** права 0600, содержимое валидно, запись атомарна (нет частичного файла
  при моке сбоя) **[локально]**
- **Given** два вызова генератора одного типа
- **When** сравнить значения
- **Then** они различаются **[локально]**

#### FR-0.6. `core/units.py`
**User story:** Как оператор, я хочу установку systemd-юнитов из шаблонов
`systemd/` одной функцией, чтобы юниты не правились руками.
**AC:**
- **Given** шаблон юнита в `systemd/` и tmp-каталог как root-префикс (мок)
- **When** вызов установки юнита
- **Then** юнит скопирован/отрендерен из шаблона, включён; повторный вызов не
  создаёт дубликат и не падает (идемпотентность) **[локально]**

#### FR-0.7. `core/protocol.py` — `ProtocolAdapter` (ABC)
**User story:** Как разработчик, я хочу единый интерфейс протокола
(name/default_port/transport; install/add_client/remove_client/status/
render_share_links/remove), чтобы Xray и Hysteria2 реализовывали один контракт.
**AC:**
- **Given** класс без всех абстрактных методов
- **When** попытка инстанцировать
- **Then** `TypeError` **[локально]**
- **Given** тестовый адаптер-заглушка, реализующий контракт
- **When** инстанцирование и вызов каждого метода с тестовыми данными
- **Then** контракт компилируется и типизируется (аннотации на всех методах) **[локально]**

#### FR-0.8. `gateway/store.py` + тесты
**User story:** Как оператор, я хочу персистентное состояние клиентов
(pydantic-модели `ClientProfile`/`GatewayState`, файл 0600), чтобы клиенты
выживали между запусками CLI.
**AC:**
- **Given** состояние с клиентом
- **When** save → load (roundtrip)
- **Then** данные эквивалентны **[локально]**
- **Given** файл состояния
- **When** `stat`
- **Then** права 0600 **[локально]**
- **Given** битый JSON в файле состояния
- **When** load
- **Then** явная читаемая ошибка, не падение трейсбеком и не молчаливая потеря **[локально]**
- **Given** пустое/отсутствующее состояние
- **When** `vds gateway status`
- **Then** команда завершается exit 0 с сообщением о пустом состоянии, без traceback **[локально]**
- **Given** удаление клиента по имени
- **When** клиент существует / не существует
- **Then** существующий удаляется; несуществующий — явная ошибка без исключения **[локально]**

### Фаза 1 — Xray + VLESS Reality

#### FR-1.1. `vds xray install`
**User story:** Как оператор, я хочу установить Xray-core с Reality на TCP 443
одной командой, чтобы получить базовый DPI-устойчивый транспорт.
**AC:**
- **Given** TCP 443 уже занят другим процессом
- **When** `vds xray install`
- **Then** установка прервана ДО изменений с внятной ошибкой `[error]` с указанием
  процесса-владельца порта **[VDS]**
- **Given** чистый VDS (Ubuntu 24.04, root)
- **When** `vds xray install`
- **Then** `systemctl is-active vds-xray` = active; `ss -tlnp` показывает слушающий
  443; конфиг `/usr/local/etc/xray/config.json` с правами 0600 **[VDS]**
- **Given** уже установленный Xray
- **When** `vds xray install` повторно
- **Then** состояние не сломано, exit 0 или явное «уже установлено», сервис active **[VDS]**
- **Given** флаг SNI-маски (по умолчанию `www.google.com`, значение задаёт владелец)
- **When** install с нестандартным SNI
- **Then** в конфиге `dest`/`serverNames` соответствуют флагу **[локально]** (проверка
  рендера), **[VDS]** (проверка на сервере)

#### FR-1.2. `vds xray add-client` + share-link
**User story:** Как оператор, я хочу добавить клиента и получить share-link
`vless://...reality...vision`, чтобы клиент импортировал его в v2rayNG/NekoRay.
**AC:**
- **Given** установленный Xray
- **When** `vds xray add-client <name>`
- **Then** клиент сохранён в store, ссылка выведена, формат соответствует
  `vless://<uuid>@<ip>:443?security=reality&sni=<sni>&fp=chrome&pbk=<pbk>&sid=<sid>&flow=xtls-rprx-vision#<name>` **[VDS]**
  (валидация формата строки — **[локально]** через юнит-тест рендера)
- **Given** сгенерированная ссылка и приватный ключ сервера
- **When** сравнение
- **Then** приватный ключ (`privateKey`) в ссылке отсутствует; в ссылке только pbk **[локально]**
- **Given** клиент с именем, которое уже существует
- **When** `vds xray add-client <то же имя>`
- **Then** явная ошибка, существующий клиент не перезаписан **[локально]** (логика store)
- **Given** вывод команды и логи
- **When** grep по выводу/логам
- **Then** UUID в логах замаскирован или отсутствует **[локально]** (тест на моках) /
  **[VDS]** (визуальная проверка вывода)

#### FR-1.3. `vds xray status`
**User story:** Как оператор, я хочу видеть активность юнита, валидность конфига,
занятость порта и последние ошибки, чтобы быстро диагностировать сбой.
**AC:**
- **Given** работающий Xray
- **When** `vds xray status`
- **Then** выведены: статус юнита, `xray -test -config` результат, порт, последние
  ошибки journal (без секретов) **[VDS]**
- **Given** Xray не установлен
- **When** `vds xray status`
- **Then** читаемое «не установлен», exit ≠ 0, без traceback **[локально]** (ветвление
  на моках) / **[VDS]**

#### FR-1.4. `vds xray remove`
**User story:** Как оператор, я хочу полностью удалить Xray, чтобы откатить фазу 1.
**AC:**
- **Given** установленный Xray
- **When** `vds xray remove` (без `--apply`)
- **Then** dry-run: показан план удаления (юнит, конфиг, бинарь, клиенты из store),
  ничего не выполнено **[VDS]**
- **When** `vds xray remove --apply` + подтверждение
- **Then** юнит stopped/disabled, файлы удалены, клиенты Xray удалены из store,
  порт 443 освобождён **[VDS]**
- **Given** Xray не установлен
- **When** `vds xray remove --apply`
- **Then** идемпотентно: exit 0 с сообщением «нечего удалять» **[локально]** (логика)
  / **[VDS]**

#### FR-1.5. TUI-пункт Xray
**User story:** Как оператор, я хочу пункт «Управление Xray» в TUI-меню, чтобы
работать без memorизации CLI-флагов.
**AC:**
- **Given** запущен `python -m src.main`
- **When** навигация по меню
- **Then** доступны действия install/add-client/status/remove, вызывающие те же
  команды, что и CLI **[локально]** (smoke: меню рендерится, пункты существуют)

#### FR-1.6. Юнит-тест рендера конфига Xray
**User story:** Как тестировщик, я хочу снапшот-тест генерации `config.json`,
 чтобы изменения конфига отслеживались без живого сервера.
**AC:**
- **Given** фиксированные входные параметры (uuid, ключи, sni, shortId)
- **When** рендер конфига
- **Then** результат совпадает с эталоном (снапшот), является валидным JSON,
  содержит `flow: xtls-rprx-vision`, `security: reality` **[локально]**
- **Given** рендер и повторный рендер с теми же входными данными
- **When** сравнение
- **Then** результат детерминирован **[локально]**

### Фаза 2 — Hysteria2 (без домена)

#### FR-2.1. `vds hysteria2 install` (self-signed, тестовый режим)
**User story:** Как оператор, я хочу поднять Hysteria2 на UDP 443 без домена
(self-signed + `insecure=true` у клиента, masquerade-decoy), чтобы получить
QUIC-транспорт для мобильных сценариев без покупки домена.
**AC:**
- **Given** UDP 443 уже занят
- **When** `vds hysteria2 install`
- **Then** установка прервана ДО изменений с ошибкой и указанием владельца порта **[VDS]**
- **Given** чистый VDS
- **When** `vds hysteria2 install`
- **Then** юнит active; `ss -ulnp` показывает слушающий UDP 443; конфиг
  `/etc/hysteria/config.yaml` 0600; сгенерирован self-signed сертификат;
  masquerade настроен на decoy-ответ **[VDS]**
- **Given** повторный `vds hysteria2 install`
- **When** второй запуск
- **Then** идемпотентно: сервис active, сертификат/пароль не перегенерированы
  (или перегенерация явно задокументирована как поведение) **[VDS]**

#### FR-2.2. `vds hysteria2 add-client` + share-link
**User story:** Как оператор, я хочу выдать клиенту ссылку
`hysteria2://<password>@<ip>:443/?sni=<sni>&insecure=1`, чтобы клиент подключился
в тестовом режиме без валидации сертификата.
**AC:**
- **Given** установленный Hysteria2
- **When** `vds hysteria2 add-client <name>`
- **Then** клиент в store; ссылка выведена; содержит `insecure=1` (тестовый режим) **[VDS]**
  (формат — **[локально]** юнит-тестом)
- **Given** вывод/логи
- **When** grep
- **Then** пароль отсутствует или замаскирован в логах (в share-link — по назначению) **[локально]**

#### FR-2.3. `vds hysteria2 status` / `remove`
**User story:** Как оператор, я хочу диагностику и полный откат Hysteria2.
**AC:**
- **Given** работающий Hysteria2
- **When** `vds hysteria2 status`
- **Then** выведены: статус юнита, UDP 443, срок действия self-signed сертификата,
  последние ошибки journal **[VDS]**
- **Given** установленный Hysteria2 и применённый sysctl-тюнинг
- **When** `vds hysteria2 remove --apply`
- **Then** юнит и конфиги удалены, клиенты удалены из store; вопрос отката sysctl —
  см. OQ-2 **[VDS]**

#### FR-2.4. Sysctl-тюнинг BBR/буферы
**User story:** Как оператор, я хочу применить `net.ipv4.tcp_congestion_control=bbr`,
`net.core.rmem_max/wmem_max` из шаблона `/etc/sysctl.d/99-vds-gateway.conf`,
 чтобы QUIC/QUIC-буферы не резали скорость.
**AC:**
- **Given** VDS до тюнинга
- **When** install (фазы 2)
- **Then** файл `99-vds-gateway.conf` создан из шаблона, значения применены
  (`sysctl net.ipv4.tcp_congestion_control` = bbr) **[VDS]**
- **Given** повторный запуск
- **When** install снова
- **Then** значения не дублируются, файл перезаписан идемпотентно **[VDS]**
- Рендер файла из шаблона — детерминирован **[локально]** (юнит-тест)

#### FR-2.5. TUI-пункт Hysteria2
**AC:**
- **Given** TUI-меню
- **When** навигация
- **Then** доступны install/add-client/status/remove для Hysteria2 **[локально]** (smoke)

### Сквозные

#### FR-X.1. Probe-resistance (проверочное свойство Reality)
**User story:** Как оператор, я хочу, чтобы `curl`/TLS-зонд с неверным или
отсутствующим SNI на TCP 443 получал ответ сайта-маски (`dest`), а не признаки
Xray, чтобы сервер не палился при активном зондировании.
**AC:**
- **Given** установленный Reality
- **When** `curl -v https://<ip>/` с чужим SNI с внешней машины
- **Then** ответ соответствует сайту-маске/dest, в ответе нет признаков прокси **[VDS]**

#### FR-X.2. Конфликт Xray/Hysteria2 на 443 отсутствует
**AC:**
- **Given** установлены оба
- **When** `ss -tlnp` + `ss -ulnp`
- **Then** TCP 443 — Xray, UDP 443 — Hysteria2, оба active одновременно **[VDS]**

## 4. Нефункциональные требования

| Категория | Требование | Как проверить |
|---|---|---|
| Безопасность — секреты | UUID, пароли, приватные ключи не попадают в логи, share-link (кроме предназначенных клиенту полей) и git | юнит-тест [локально] + grep вывода [VDS] |
| Безопасность — права | `state.json`, `config.json`, `config.yaml`, ключи — 0600 | `stat` [VDS]; тест store [локально] |
| Безопасность — порты | Перед установкой обязательна проверка занятости порта (`port_free`) | FR-1.1/FR-2.1 AC занятого порта |
| Идемпотентность | Повторный `install` каждой фазы не ломает состояние и не перегенерирует секреты молча | двойной прогон [VDS]; тесты store/units [локально] |
| Root | Команды install/remove/status без root завершаются читаемой ошибкой до любых изменений, без traceback | прогон без sudo [VDS] |
| Dry-run/откат | `remove` — dry-run по умолчанию + `--apply`; откат install = remove --apply; план отката задокументирован в SPEC | ручная проверка [VDS] |
| Блокировки | Мутирующие операции под `core.lock.FileLock` | code review + SPEC |
| Downtime | Установка Xray на сервере с занятым 443 не должна останавливать существующий сервис | FR-1.1 AC занятого порта |
| Локальная тестируемость | Все юнит-тесты фаз 0–2 проходят без root, сети, Docker (`pytest -q` exit 0) | CI/локальный прогон |
| Вывод | rich-вывод с тегами `[info] [success] [warning] [error] [change]` через `core.logger` | code review |
| Shell | Новый код — только `run_list`/списки через `core/shell.py`, без `shell=True` | grep/review |

- Hysteria2 без домена: self-signed + `insecure=true` (тестовый режим),
  masquerade-decoy, sysctl BBR/буферы, install/add-client/status/remove,
  share-link, TUI-пункт.
- Частичная приёмка фаз 1–2 на живом VDS по чеклисту (AC с маркировкой [VDS]).

**Не входит (явно):**
- XHTTP / CDN-фронт (фаза 3 roadmap).
- AmneziaWG (фаза 4).
- Hub/подписки/`gateway init`/reconcile/export (фаза 5) — кроме `gateway status`
  на пустом состоянии (FR-0.8) и `gateway/store.py`.
- ACME/Let's Encrypt, домены, ротация ключей (фаза 6).
- Watchdog/healthcheck/метрики/dashboard-интеграция (фаза 7).
- Docker e2e-скелет (отнесён к фазе 8, вне скоупа).
- TECHDEBT P4–P6 (в скоупе фазы 0 только P1–P3).
- SNI-мультиплексор/nginx stream (фаза 5), NaiveProxy, TUIC, Snowflake.

## 6. Крайние случаи

| # | Случай | Ожидаемое поведение | AC-ссылка |
|---|---|---|---|
| E1 | TCP 443 занят при `xray install` | отказ ДО изменений, имя процесса в ошибке | FR-1.1 |
| E2 | UDP 443 занят при `hysteria2 install` | аналогично | FR-2.1 |
| E3 | Битый/отсутствующий `state.json` | читаемая ошибка, отсутствие молчаливой потери | FR-0.8 |
| E4 | Повторный запуск install (обе фазы) | идемпотентность, секреты не перевыпускаются молча | FR-1.1, FR-2.1, NFR |
| E5 | Нет root | отказ до изменений, без traceback | NFR |
| E6 | Обрыв сети при скачивании Xray-бинаря | установка прервана, частичные файлы не оставлены как «готовые», повторный запуск succeeds | FR-1.1 (частично проверяемо только [VDS]) |
| E7 | `add-client` с дублирующимся именем | ошибка, без перезаписи | FR-1.2, FR-0.8 |
| E8 | `remove --apply` при неустановленном сервисе | exit 0, «нечего удалять» | FR-1.4 |
| E9 | `xray -test -config` невалиден после рендера | `status` показывает ошибку конфига явно | FR-1.3 |
| E10 | Истекающий/истёкший self-signed сертификат Hysteria2 | `status` показывает остаток дней | FR-2.3 |
