# REQ-20261112-transport-hardening — roadмап укрепления транспортов (Salamander + AWG-ротация)

## Мета
- **Источник:** анализ заметности каналов для DPI (CENSORSHIP-PATTERNS §2a,
  2026-11-12) + решение владельца «продумать общий roadmap для Salamander и
  AWG-ротации» (чат 2026-11-12).
- **Автор:** аналитик (vds-analyst), оформление оркестратором
- **Дата:** 2026-11-12
- **Статус:** draft (G0-G1) — ждёт подтверждения владельца на скоуп

## 1. Проблема (зачем)

Два транспорта имеют известные слабости заметности без инструментов быстрого
ответа:

1. **Hysteria2 (mob)** — «голый» QUIC к нелеловому IP: самый заметный протокол
   при активном использовании; шейпится первым. Протокол поддерживает
   obfs=salamander (маскировка UDP под шум) — **в проекте не реализован**
   (проверено grep'ом 2026-11-12: сервер/клиент/конфиг — пусто).
2. **AWG (основная схема)** — единственный живой в TSPU-окна; при переходе
   цензора к адресному блоку UDP (сигнатуры-обход не спасают от
   поведенческого блок-листа IP:порт) ответ возможен только **ротацией
   параметров обфускации и/или порта** — сейчас это ручные правки конфигов на
   сервере и ноутбуке под стрессом. Инструмента нет (grep 2026-11-12).

UDP-over-TCP (обёртка AWG в TCP) — **вне скоупа этого REQ**: нужен только при
тотальной блокировке UDP, которой не наблюдалось (AWG-UDP пережил все
эпизоды 2026-11-11..12). Отложено в CENSORSHIP-PATTERNS §2a как план
эскалации уровня 2.

## 2. Скоуп: два независимых цикла, общий принцип

**Общий принцип «мягкого rollout»** (наследуется из CDN-цикла, ADR-006):
любое изменение не ломает существующих клиентов — новый профиль поднимается
ПАРАЛЛЕЛЬНО старому (новый порт), пере-импорт ссылок клиентами, затем старый
гасится. Reality-gate-аналог: работоспособность остальных каналов не
нарушается.

### Цикл H-OBFS: Salamander для Hysteria2 (малый WP, ~0.5–1 день)

- **FR-1** Сервер: параметр obfs в hysteria2-инблэнд (`obfs: {type:
  salamander, password: <генерён>}`); секрет в gateway/state.json (0600,
  маскирование в выводе — общее).
- **FR-2** Share-link: стандартные параметры URI hysteria2
  (`obfs=salamander&obfs-password=…`).
- **FR-3** Клиент (vpn-manager): парсер двух параметров + генерация `obfs:`
  в YAML-конфиге клиента; тесты на оба.
- **FR-4** Мягкий rollout: obfs-профиль поднимается на **новом UDP-порту**
  параллельно живому 443/udp; команда `vds hysteria2 add-obfs --port <N>`
  (+ `remove-obfs`); клиенты пере-импортируют, старый порт гасится
  `remove-obfs`.
- **FR-5** Ротация пароля obfs: `vds hysteria2 rotate-obfs` (новый пароль на
  новом порту — тот же мягкий путь; direct-ротация на живом порту запрещена).
- **AC (приёмка):** e2e через obfs-порт (204, замер скорости ≥ голого QUIC −20%);
  Reality/XHTTP/CDN не задеты (gate); monitor/doctor — зелёные; grep журналов
  без секретов; при блокировке «голого» QUIC-тестом (внешний probe к 443/udp
  через TSPU-флап) obfs-порт продолжает работать — на живой машине проверяется
  эксплуатационно, в тестах — конфигурная часть.

### Цикл A-ROTATE: ротация параметров AWG (малый WP, ~0.5–1 день)

- **FR-6** `vds amneziawg rotate-params [--instance <name>] [--apply]`:
  генерация нового набора (Jc 4–12, Jmin/Jmax согласованы, S1/S2 10–128,
  H1–H4 уникальные ≠ 5/1701/…) в серверный шаблон и **все клиентские .conf**;
  dry-run по умолчанию (конвенция деструктивных операций).
- **FR-7** `vds amneziawg set-port <N> [--apply]`: новый ListenPort + UFW
  allow + client Endpoint (мягкий путь: новый порт параллельно, откат = возврат
  порта).
- **FR-8** Клиент (vpn-manager): `vpn amneziawg sync` — подтянуть обновлённый
  .conf по ssh/scp (механизм add-client уже умеет; обобщить на существующий
  клиент), рестарт локального инстанса после подтверждения серверного.
- **FR-9** Краткий разрыв туннеля при ротации — документирован (10–20 с);
  команда печатает об этом до применения.
- **AC (приёмка):** живой e2e — rotate-params на реальном туннеле, reconnect
  ноутбука ≤ 30 c, handshake свежий, split жив; rollback = revert параметров
  (старый набор сохраняется в backup-файл conf).

### Цикл R-ROTATE: ротация маски/порта Reality (опциональный, ~0.5 дня)

Предмет иной, чем у AWG: у Reality **нет параметров обфускации** (стелс и так
= валидный TLS) — ротируются **маска (dest/SNI), порт и ключи клиентов**.
Лечит специфическое душение паттерна SNI/порта; **не лечит** IP-троттлинг
(главный наблюдённый вектор — слой CDN/relay, не этот цикл).

- **FR-10** `vds xray rotate-mask --dest <url-or-ip:port> [--apply]`: новый
  dest в realitySettings (serverNames/PrivateKeyRegen опц.) + обновление
  share-линков (sni=); dry-run по умолчанию; мягкий путь — при смене dest
  инблэнд пересоздаётся на том же порту (разрыв ~5 с), клиенты пере-импортируют.
- **FR-11** Параллельный порт: `vds xray add-reality-port <N>` (второй
  Reality-инблэнд тем же dest, UFW, отдельные клиенты) — без разрыва;
  `remove-reality-port` гасит старый после пере-импорта.
- **FR-12** Валидация dest: handshake-проба с сервера (TLS 1.3, H2, не
  Cloudflare-CDN домен — иначе fingerprint-конфликт) до применения; список
  «проверенных масок» в docs.
- **AC (приёмка):** e2e на новом dest/порте (Reality-gate 204), остальные
  каналы не задеты; rollбack = возврат прежнего dest (backup conf).

### Цикл D-SPEED: speed-probe — детекция «тихой деградации» (клиентский, ~0.5 дня)

Клиентский WP (vpn-manager), серверная часть не нужна. Закрывает известный
GAP: probe судит канал по generate_204 (204 байта) — быстр даже под душением,
«тихая деградация» (bulk-скорость просела, latency ок) невидима.

- **FR-13** `vpnm/probe.py`: после latency-замеров — bulk-сэмпл на профиль
  (curl скачать 1 MB с `speed.cloudflare.com/__down?bytes=1000000` через socks,
  timeout 15 c, замер speed_download). Результат — Мбит/с в новой колонке
  таблицы probe; при timeout/недоборе → speed=null.
- **FR-14** Классификация: profile.status = "degraded", если latency ok,
  но speed < DEGRADED_MBPS (дефолт 2 Мбит/с, флаг --min-speed). Degraded
  участвует в switch **последним** (не выбирается «быстрейшим», если есть
  недеградированная альтернатива).
- **FR-15** `vpn probe --no-bulk` — отключить bulk-сэмпл (быстрый probe);
  `--bulk-bytes N` — размер сэмпла.
- **FR-16** monitor/doctor: строка vpnm показывает и speed; degraded —
  отдельный статус в matrix (жёлтый).
- **AC:** юнит-тесты (моки curl): degraded-логика, --no-bulk, сортировка
  switch; живой прогон на 4 профилях — колонка заполнена; при душении
  TCP (эксплуатационно) reality/xhttp получают degraded, AWG/CDN — ok.

### Цикл H-HOP: port-hopping Hysteria2 (сервер+клиент, ~0.5–1 день)

Против **порто-специфичного** шейпинга UDP (не IP-wide — тот не лечится,
см. §3a). Механика Hysteria2: клиент прыгает по диапазону портов, сервер
принимает весь диапазон через nft-редирект на реальный порт.

- **FR-17** Сервер: `vds hysteria2 add-hop-ports <range> [--apply]`
  (напр. 20000-20100): nft rule `inet nat prerouting udp dport <range>
  redirect to :443` + UFW allow range/udp; идемпотентно; `remove-hop-ports`.
- **FR-18** Share-link: параметр `mport=<range>` в hysteria2:// URI
  (стандарт клиента hysteria2).
- **FR-19** Клиент (vpn-manager): парсер `mport` + генерация в YAML
  (server: host:443 + ports: <range>); тесты.
- **FR-20** Мягкий rollout: диапазон добавляется параллельно — живой 443/udp
  не трогается; клиенты пере-импортируют по желанию.
- **AC:** юнит-тесты парсера/генератора; живой e2e: соединение через
  диапазон (клиент лог «hopping»), скорость не деградировала vs 443;
  Reality/XHTTP/CDN gate — не задеты.

### Отложено (не в этом REQ)

- **UDP-over-TCP** (udp2raw/phantomtun на обеих сторонах) — эскалация уровня 2
  при тотальном UDP-блоке; критерий активации: AWG-UDP перестал подниматься
  при живом TCP-канале. Лежит в CENSORSHIP-PATTERNS §2a.
- **CDN-IP scanner / ротация edge-IP** — отдельный REQ.

## 3. Порядок и зависимости

```
H-OBFS и A-ROTATE независимы друг от друга (разные протоколы/файлы).
Рекомендуемый порядок: **D-SPEED первым** (полдня, чисто клиентский, даёт
наблюдаемость деградации для всех остальных решений); затем A-ROTATE
(«план Б» основной схемы), H-OBFS (mob), H-HOP (порто-специфичная защита
mob — вместе с H-OBFS в одну приёмку), R-ROTATE — опционально последним.
D-SPEED и H-HOP/H-OBFS независимы; A-ROTATE/R-ROTATE независимы от всех.
Каждый цикл: аналитик(этот REQ) → архитектор(SPEC WP) → кодер → тестер(G4)
→ приёмка на живой машине.
```

## 4. Риски

| риск | мера |
|---|---|
| rotация параметров при «плохих» значениях (невалидная комбинация Jmin>Jmax) | генератор с валидацией + unit-тесты диапазонов |
| клиенты-«призраки» (конфиг скачан, но юнит не рестартнут) | FR-8: sync печатает «нужен рестарт»; tunnel status покажет handshake протух |
| блок obfs-порта ТСПУ как «неизвестный UDP» | это и есть класс AWG-риска; ответ = A-ROTATE (у Hysteria2 свой пароль обфускации — rotate-obfs) |
| чрезмерное усложнение (комбайн) | оба цикла — малые WP; UDP-over-TCP осознанно отложен |

## 5. Трассируемость

CENSORSHIP-PATTERNS §2a (анализ) → этот REQ → SPEC (по циклам) → WP кодера →
G4 тестера → живая приёмка. Связь: ADR-005 (AWG-транспорт), SPEC-20261110-amneziawg.
