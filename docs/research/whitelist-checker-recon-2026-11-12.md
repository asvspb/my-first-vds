## 2. Факты

- **bschekbot жив и развит**: ping/TCP/TLS/HTTP/DNS + готовые VPN-конфиги
  (VLESS/Reality, Hysteria2, VMess, Trojan, SS) + замедление скорости. Операторы:
  МТС, МегаФон, Билайн, Т2, Yota, Т-Мобайл, СберМобайл; «десятки городов».
  **Есть API** (bsbord.com/api), паттерн использования «только бесплатные методы»
  `[подтверждено: код remnawave-bedolaga]`. Модель доверия — чёрный ящик:
  механика подтверждения региона не раскрыта, вендор видит проверяемые хосты.
- **cheburcheck — другой класс**: реестр блок-лист + **собственные whitelist-данные
  через волонтёрские ноды** (Reporter, open-source) — модель DIY-черкера.
  Проверка VPN-конфигов не заявлена.
- **eByeBots** — аудит сайтов, whitelist-часть делегирует API bschekbot; отсечено.
- Масштаб whitelist: ~900 ресурсов (IXBT 2026-11-12); режимы в западной части РФ,
  включая СПб (Фонтанка 2026-11-09) и Москву эпизодически; мобильный трафик Q2 −6%.
- ru-whitelist-check — только «IP в списке?», не заменяет живой тест.

## 4. Вердикт

**Go на существующий бот, гибрид на дистанции.** bschekbot закрывает ровно наш
use-case (наши инбаунды × мобильные операторы × whitelist), жив ≥4 мес, есть API.
Доверие закрывается методикой И21 (≥2 независимых чекеров + контрольный мёртвый
инбаунд), не вендором. Свой стенд — когда появится точка в whitelist-регионе.

## 5. Что проверить дальше

1. Прогон bschekbot на одноразовом Reality-инбаунде + второй чекер; зафиксировать регион·провайдер.

3. Вопросы вендору: хранение хостов, подтверждение региона, тарифы API.
