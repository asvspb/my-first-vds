# Карта анти-DPI фич от внешней модели + сверка с нашим контуром

- **Дата:** 2026-11-22 · **Источник:** внешняя LLM (app-architect контекст), запрос
  владельца «сохрани ценное». Snapshot ответа, сверен с нашим контуром (колонка
  «У нас») — как в [notifications-and-resilience-2026-11-17](notifications-and-resilience-2026-11-17.md).
- **Главный тезис источника:** «волшебных криптосистем против DPI» в открытом
  доступе нет; устойчивость даёт не секретный шифр, а **экономическая стоимость
  блокировки** (collateral damage — цензор не может заблокировать тебя, не
  сломав пол-интернета). Вкладывались США в: Tor/Pluggable Transports
  (NRL), Domain Fronting (meek), Refraction Networking / Decoy Routing
  (TapDance, Conjure — DARPA/NSF, прокси на транзитном маршрутизаторе;
  владельцу VDS недоступно, но принцип показателен).
- **Связь с нашими доками:** [CENSORSHIP-ROADMAP](../CENSORSHIP-ROADMAP.md),
  [CENSORSHIP-PATTERNS](../CENSORSHIP-PATTERNS.md),
  [GROWTH-POINTS](../GROWTH-POINTS.md), intake фич — через cycle (как И40–И45).

## 1. Активный пробинг

| Фича | У нас |
|---|---|
| Silent Drop (ни RST, ни ICMP без валидного токена) | ✅ AWG по сути; Reality — см. ниже |
| TLS-маскировка чужим сайтом (XTLS-Reality: dest/serverNames, пробер уходит на настоящий сайт) | ✅ в бою (dest=www.google.com, проверено 5/5) |
| Реалистичный HTTP-маскарад (Hy2/Trojan/NaiveProxy fallback с HTTP/2-3 заголовками) | 🟡 Reality-fallback есть; masquerade-поведение Hy2 в нашем конфиге не проверялось |
| Replay-защита (timestamp-окна, кэш nonce против переигрывания ClientHello) | 🟡 встроено в Reality/Xray; отдельно не валидировалось |
| drop all по умолчанию, без панелей, SSH изолирован | ✅ UFW harden (SPEC-20261116), ssh 49222, 3x-ui отсечён |
| Разделение клиентских и межузловых портов | ✅ P24: awg2 51900–51911, клиенты не задеты |
| Телеметрия пробинга + адаптивная реакция (осторожно: селективный бан сам маркер) | ✅ probe-watch + threat-level; auto-lockdown осознанно off |
| Decoy Routing (прокси на транзитном ISP) | ❌ недоступно владельцу VDS; принцип collateral damage |

## 2. Пассивный DPI (первый пакет, SNI, QUIC)

| Фича | У нас |
|---|---|
| Реальный сетевой стек Chromium (NaiveProxy/Cronet — не имитация, а настоящий Chrome) | ❌ кандидат в intake |
| uTLS-имитация отпечатка + TLS 1.3 (против JA3/JA4 Go/OpenSSL) | ✅ клиентские профили (fp=firefox 5/5) |
| AWG-обфускация: мусор Jc/Jmin/Jmax, паддинг S1–S2, магия H1–H4 | ✅ в бою |
| **AWG 1.5+ CPS-пакеты (I1–I5): мимикрия под конкретные UDP-протоколы (QUIC/DNS/SIP), а не шум** | ❌ **новая идея — проверить поддержку в нашей версии AWG** |
| Hy2 + Salamander (шифрование заголовка QUIC) | ✅ в бою; ⚠️ риск: ТСПУ режет весь нераспознанный high-entropy UDP на зарубежные AS — чистый шум уязвимее мимикрии |
| XHTTP (SplitHTTP: разделение потоков, padding, xmux) | 🟡 XHTTP есть (8443); xPaddingBytes/xmux — упомянуты в анти-ML GR-22, глубина конфига не валидировалась |
| WebTunnel (WebSocket поверх Nginx/Caddy) | ❌ кандидат |
| MASQUE (HTTP/3 CONNECT-UDP; Apple Private Relay / WARP) | ❌ кандидат — режется только с ущербом обычному вебу |

## 3. Поведенческий анализ, TLS-in-TLS, срез ~16–20 КБ

| Фича | У нас |
|---|---|
| Анти-TLS-in-TLS (XTLS-Vision: паддинг первых пакетов; xPaddingBytes, IAT-mode) | 🟡 xPaddingBytes/xmux упомянуты (GR-22); Vision-режим не в бою |
| Port Hopping против 5-tuple-трекинга | ✅ hop 20000–20500 (nft DNAT) |
| Лимитирование жизни TCP-потоков (xmux переоткрытие до порога) — против среза 16 КБ | 🟡 проверить наш xmux-профиль; помогает только если ТСПУ считает на 5-tuple, а не на пару IP |
| Транзит через RU-relay (вход в своей AS, трансграничный срез не применяется к клиенту) | ✅ каскад в бою |

## 4. Инфраструктура и топология

| Фича | У нас |
|---|---|
| Эшелонирование: ≥1 TCP/TLS + ≥1 UDP-обфусцированный + резерв через другой маршрут | ✅ Reality/Hy2/AWG/XHTTP + ADR-016 (awg ↔ wstunnel) |
| Каскад Клиент→RU-relay→Exit с манёвром ноги (нога сама проходит трансграничный ТСПУ = критическая точка) | ✅ P24/P25 закрыты, манёвр + селектор носителей |
| Незасвеченные AS / ротация IP (вместо топ-5 хостеров) | 🟡 v4 = один IP (известный SPOF, resilience-review); **V6-EXIT: /48 на asv2 готов к ротации** |
| Резервные P2P/WebRTC-мосты (модель Snowflake) — на сценарий жёстких белых списков | ❌ идея дальнего горизонта |
| План Б: резервный канал/второй exit (наш Q6) | 🧊 решено: CDN-канал = холодный резерв (Q6 `f5794ce`), канал мёртв 20.11 (апекс без A-записи) |

## 5. Асимметрия и «невидимые» поломки

| Фича | У нас |
|---|---|
| DoH/DoT в туннеле, защита от DNS-спуфинга (подмена DNS раньше подключения) | ✅ vpn doh on + boot-guard; split-TLD профиль |

| Двусторонняя диагностика (сервер не видит DNS-подмену/фейковый RST/троттлинг через ретрансмиты — только корреляция клиент+сервер) | ✅ архитектура есть (guard + probe-watch); **детекторы «тихого удушения» (ss -tni retrans/RTT, tx/rx-асимметрия) = скоуп guard v1.1** — после G6 |

## Итог для планирования (прирост сверх текущей архитектуры)

1. **CPS-пакеты AWG 1.5 (I1–I5)** — мимикрия под легитимный UDP вместо шума;
   проверить версию AWG на узлах (наша — 1.0.0 dkms, см. relay-leg-diag).
2. **Полноценный HTTP-эшелон** — XHTTP есть; кандидаты на добор: NaiveProxy/Cronet,
   WebTunnel, MASQUE — на случай закручивания гаек по Reality и high-entropy UDP.
3. **Детекция «тихого удушения»** — уже запланирована (guard v1.1, после G6/24.11).
4. **План Б на бан IP/AS** — Q6 закрыт (CDN холодный резерв); живой резерв =
   V6-EXIT из /48 при бане v4.
5. **xmux/xPaddingBytes глубина** — инвентаризация текущих значений против
   16KB-срезов (пассивная проверка конфига, без живого эксперимента).
