## 1. Проблема

У WireGuard / AmneziaWG 1.5 есть фундаментальное свойство: он держит **один
долгоживущий UDP-сокет** (`client_ip:sport ↔ server_ip:51825`), перебирает ключи
(rekey) каждые 120 секунд, но сам 5-tuple (`sport/dport`) не меняет часами,
а заголовки `H1–H4` в AWG 1.5 статичны. Для ML-модели АСБИ это выглядит как
«многочасовой UDP-поток на один порт с фиксированными константами в первых
4 байтах».

## 2. Четыре механизма (не светя другие протоколы на том же IP)

### 2.1. Серверный UDP Port Hopping (UDP 20000:20500 → 51825) + ротация клиентского Endpoint / ListenPort

- **Сервер (`vds`):** точно как в `src/hysteria2/hop.py`, вешаем
  `iptables -t nat -A PREROUTING -p udp --dport 20000:20500 -j REDIRECT --to-ports 51825`.
  Ядерный `awg0` продолжает слушать 51825 и не перезапускается, не рвёт туннель
  и не теряет рукопожатие.
- **Клиент (`vpnm`):** WireGuard/AWG поддерживает Seamless Roaming (бесшовную
  смену IP/порта пира без пересоздания интерфейса), поэтому легковесный таймер
  на клиенте раз в 3–7 минут (с рандомным джиттером) делает:

```bash
awg set awg0-split peer <PUBKEY> endpoint <SERVER_IP>:<RANDOM_PORT_20000_20500>
# опционально:
awg set awg0-split listen-port <NEW_RANDOM_SPORT>
```

**Эффект:** TCP-состояние внутри туннеля (видео, загрузки, звонки) не рвётся
ни на миллисекунду, но для внешнего DPI/NetFlow каждые 3–7 минут старый UDP-поток
(`sport_1, dport_1`) умирает и рождается совершенно новый (`sport_2, dport_2`).
Никакого «3-часового гигабайтного сокета» в телеметрии ТСПУ больше не существует.

### 2.2. Переход с AWG 1.5 на AWG 2.0 (диапазонные `H1–H4` + `S3/S4` + `I1–I5`)

- В AWG 1.5 заголовки типов пакетов (`H1..H4`) — это 4 конкретных числа
  (константы в каждом пакете).
- В AWG 2.0 каждый заголовок задаётся диапазоном (`H1 = 100000-200000`,
  `H2 = 200001-300000` и т.д.), поэтому каждый новый пакет и каждое перестроение
  ключей (rekey раз в 2 мин) имеют разные первые 4 байта, плюс добавляется
  рандомный padding к `CookieReply` (`S3`) и `TransportData` (`S4`),
  а перед рукопожатием выстреливается цепочка `I1–I5` (имитация QUIC Initial / DNS).

### 2.3. Радиомолчание в простое (И44 — уже в коде) + rekey-джиттер

Уже убрали `PersistentKeepalive = 25` по умолчанию (коммит `8979673`). Когда
трафика нет, туннель физически молчит, и после 180 секунд неактивности следующее
обращение пользователя начинает новую криптосессию с новой пачкой мусорных
пакетов `Jc` (`Jmin..Jmax`).

### 2.4. Что уже есть и чего не хватает

| Механизм | Сейчас | Нужно |
|---|---|---|
| UDP hop 20000–20500 → 51825 | нет для AWG (есть только Hy2 hop) | `src/amneziawg/hop.py` по образцу `src/hysteria2/hop.py` + nft/iptables-цепочка + юнит/таймер |
| Ротация endpoint/listen-port на клиенте | нет | таймер с джиттером 3–7 мин в `vpnm` (только при активном AWG, не трогать при `idle`) |
| AWG 2.0 (`S3/S4`, диапазонные `H*`, `I1–I5`) | валидатор AWG 1.5 отвергает 2.0 | ADR + расширение генератора/валидатора + совместимость с клиентами |
| Радиомолчание / rekey | `PersistentKeepalive` off (И44) | проверить `rekey`-джиттер и поведение на мобильных NAT |

## 3. Риски и ограничения

| Риск | Контрмера |
|---|---|
| Смена `listen-port` ломает NAT-маппинг у мобильного оператора | сохранять keepalive только при необходимости (`--keepalive`), ротация только при живом трафике; откат — вернуть прежний endpoint |
| Hop-диапазон самим фактом существования выдаёт «нестандартный UDP» | диапазон выбирать вне 51820–51830 и согласовать с портом 443-профиля релея |
| AWG 2.0 не поддерживается клиентом AmneziaVPN | матрица клиентов + feature-detect; не включать по умолчанию до полевой приёмки |
| Ротация рвёт handshake на некоторых ядрах | тест seamless roaming на 2–3 ядрах; при отказе — только endpoint, без `listen-port` |
| ML-модель увидит корреляцию «новый sport каждые 3–7 мин» | джиттер + случайный выбор порта + отсутствие метронома в простое |

## 4. Кандидаты в AC (для будущего REQ/SPEC)

1. `vds amneziawg hop install --range 20000:20500 --apply` (dry-run по умолчанию):
   REDIRECT на 51825, `awg show` не теряет handshake, `ss` видит только 51825.
2. `vpn awg rotate-endpoint --interval 3-7m` (opt-in): `awg show` фиксирует смену
   `endpoint`/`listen-port`, handshake восстанавливается ≤ 5 с, пользовательский
   TCP-поток не рвётся (проверка скачиванием).
3. AWG 2.0: генератор принимает `S3/S4`, диапазонные `H*`, `I1–I5`; `awg-quick`
   поднимает интерфейс; старый клиент 1.5 отвергается с внятной ошибкой.
4. Радиомолчание: при `idle` нет периодических пакетов (tcpdump 180 с), при
   возобновлении — новая сессия.
5. Матрица клиентов: AmneziaVPN (desktop/Android), `awg-quick` 1.5/2.0 — что
   реально импортирует и держит.

## 5. Границы

- Это **не** часть [SPEC-20261116-xhttp-xmux-padding](../team/specs/SPEC-20261116-xhttp-xmux-padding.md):
  там TCP/XHTTP, здесь UDP/AWG. Спеки не смешивать.
- Изменение параметров AWG — только через ADR (меняет протокол и совместимость
  клиентов), а не «фикс на ходу».
- Приоритет относительно GR-03 (Hy2 hop) и W1-1 (probe-watch) определяет
  владелец; без полевой приёмки на мобильном операторе не включать по умолчанию.
