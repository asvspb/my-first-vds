# ADR-008: Port hopping Hysteria2 — iptables-chain + REDIRECT + oneshot-юнит, не отдельная nft-таблица

- **Дата:** 2026-11-12
- **Статус:** accepted
- **Контекст SPEC:** [SPEC-20261112-p0-transport-upgrade](../team/specs/SPEC-20261112-p0-transport-upgrade.md) (WP-1)
- **Связанные:** ADR-002 (пути/юниты), REQ-20261112-transport-hardening (цикл H-HOP, FR-17..20)

## Контекст

Hysteria2 слушает один UDP-порт (443). Port hopping (клиент прыгает по диапазону
портов, сервер принимает весь диапазон) требует dNAT-редиректа диапазона на
слушающий порт. Сервер: Ubuntu 24.04, UFW поверх iptables-nft; проектные
конвенции — shell только через `run_list`, systemd-юниты только из шаблонов
`systemd/`, идемпотентность, права/секреты по ADR-002.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| **iptables -t nat, выделенная цепочка `VDS_HY2_HOP` + REDIRECT (выбран)** | один бекенд с UFW (iptables-nft), правило живёт в nat/PREROUTING — до UFW-фильтрации, конфликта нет; `-C`-проверка даёт естественную идемпотентность; удаление = flush одной именованной цепочки | правила не переживают ребут — нужна персистентность |
| Отдельная nft-таблица `inet vds` | современный синтаксис, table survive нет (тоже нужен reload) | второй бекенд рядом с UFW/iptables-nft — два источника правды о файрволе; в проекте нет nft-утилит в использовании; сложнее отлаживать |
| Несколько слушающих инблэндов hysteria2 (по порту) | без файрвола | hysteria2 = один listen на инстанс → N процессов и N юнитов; диапазон 100+ портов нереализуем |
| iptables-persistent / netfilter-persistent | персистентность «из коробки» | новый пакет-зависимость; сохраняет ВСЮ таблицу — риск задеть чужие правила при откате |

## Решение

1. **Механизм:** `iptables -t nat`, выделенная цепочка `VDS_HY2_HOP`
   (`-N`, при наличии не создаётся повторно), в ней по одному правилу на
   диапазон: `... -p udp --dport <start>:<end> -j REDIRECT --to-ports 443`;
   jump из `PREROUTING` (`-C` перед `-A` — идемпотентно). Удаление —
   удаление jump + flush/delete цепочки, точно не трогает чужие правила.
2. **Персистентность (ребут):** рендер apply-скрипта
   `/usr/local/sbin/vds-hy2-hop-apply.sh` (без секретов, 0755, идемпотентен —
   тот же `-C`-паттерн) + oneshot-юнит из шаблона
   `systemd/vds-hysteria2-hop.service.tpl` (`WantedBy=multi-user.target`,
   `After=network-online.target`), устанавливается через
   `core.units.install_unit`. Паттерн — как deploy-hook ACME (ADR-004):
   артефакт, перегенерируемый командой, руками на сервере не правится.
3. **UFW:** ровно одно правило на диапазон `ufw allow <start>:<end>/udp`
   (порт-фильтрация UFW идёт после nat/PREROUTING — редирект не заменяет
   need in allow); удаление — `ufw delete allow ...`. Остальная UFW-политика
   не трогается.
4. **Ширина диапазона** — ограничение в коде: 1..1000 портов (защита от
   случайного `1000-65000`); значения по умолчанию нет — диапазон всегда
   явный аргумент.

## Последствия

- Положительные: nat-правило срабатывает до UFW (порядок гарантирован
  netfilter); именованная цепочка = чистый откат; `run_list`-only, без
  `shell=True`; диапазон не открывает ничего кроме UDP-редиректа на 443.
- Отрицательные: iptables-правила в двух местах (chain + UFW-правило) —
  remove обязан чистить оба; на системах с чистым nftables (без
  iptables-компатибилити) не сработает — Ubuntu 24.04 целевая ОС, принимается.
- Трудно изменить позже: имя цепочки и путь скрипта локализованы в
  `gateway/paths.py`; смена — новый ADR.

## Как откатить

1. `vds hysteria2 remove-hop-ports --apply` — удаление jump+цепочки, UFW
   delete, удаление юнита и скрипта (само собой dry-run по умолчанию).
2. Ручной эквивалент (если CLI недоступен):
   `iptables -t nat -F VDS_HY2_HOP && iptables -t nat -D PREROUTING -j VDS_HY2_HOP && iptables -t nat -X VDS_HY2_HOP`,
   `ufw delete allow <range>/udp`, `systemctl disable --now vds-hysteria2-hop`.
3. Живой канал udp/443 не прерывается ни на одном шаге (правило только
   добавляет путь).
