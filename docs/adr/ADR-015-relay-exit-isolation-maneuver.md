# ADR-015 — Изоляция межузлового порта exit и манёвр ноги relay↔exit

- **Статус:** предложен (G2), 2026-11-20
- **Связано:** ADR-007 (RU-relay), ADR-008 (статический пул портов + REDIRECT как паттерн),
  TECHDEBT P24/P25, `docs/team/reports/TEST-20261120-relay-leg-diag.md` (WP-M0)
- **Заменяет:** — (не заменяет; уточняет границу доверия ADR-007 §R4)

## Контекст

На exit-узле (asv2) единственный `awg0` слушает `51825/udp`; этот же порт —
клиентские пиры (10.9.0.2–10.9.0.4) и нога релея (10.9.0.5). Ограничить порт по IP
релея нельзя без риска для клиентов (P24). Нога периодически деградирует: за 7 дней
35 эпизодов, медиана 7 мин, максимум 306 мин (cooldown-корректированные данные).

WP-M0 показал: **возраст handshake не эквивалентен недоступности** — наблюдался
«blocked» при `latest handshake` 5 ч 11 мин, но данные через ногу шли
(`ping -I awg1` 2/2, `curl --interface awg1` HTTP 200). Значит строить автомат
на `handshake_age` нельзя.

## Решение

1. **Выделенный интерфейс ноги на exit**: `awg2` (подсеть `10.11.0.0/30`,
   exit `10.11.0.1`, релей `10.11.0.2`), отдельный от клиентского `awg0`.
2. **Статический пул UDP-портов на exit** (паттерн ADR-008): базовый порт
   `P_base = 51900`, пул `51900–51911` (12 портов), все слушаются 24/7;
   `nft`/`iptables` REDIRECT c `saddr == <relay-ip>` на `P_base`;
   UFW — только `allow from <relay-ip> to any port P_base`.
3. **Манёвр — локальный на релее**: `awg set awg1 listen-port <new>
   peer <pub> endpoint <exit-ip>:<next_pool_port>` (runtime, без рестарта
   `vds-relay-exit`, без разрыва `table 100`/policy-routing), затем атомарная
   запись `Endpoint` в `/etc/amnezia/awg1.conf` (0600, `.bak-pre-maneuver`).
4. **Триггер — data-plane liveness, не handshake**: проба внутри туннеля
   (`ping -I awg1 10.11.0.1` и/или TCP до exit через туннель) + отсутствие
   прироста `rx` при живом трафике на `awg0`. Activity gate: простой без трафика
   никогда не триггерит манёвр.
5. **Базовая митигация**: `PersistentKeepalive = 25` на `awg1` (и на `awg2`-пире
   exit) — WP-M0 подтвердил, что keepalive инициирует handshake за ~30 с.
6. **Двухступенчатое включение**: сначала ручной актуатор
   (`vds relay maneuver step --apply`, `status`, `history`, `rollback`),
   затем opt-in таймер (`--enable-auto`, по умолчанию выкл).
7. **Резерв (если UDP-пул не помогает)**: IPv6-нога `relay → exit` по уже
   существующим адресам (WP-M0: 47 мс, TCP6/443 OPEN) — без новых портов;
   TCP-Reality fallback — отдельный WP после MVP.

## Граница доверия (инвариант)

RU-релей **не получает** SSH/API/ключей управления exit-узлом (AGENTS §6,
ADR-007 §R4). Пул портов и `awg2` статически развёрнуты на exit; релей лишь
меняет локальный endpoint. Компрометация релея не даёт прав на exit.

## Альтернативы

1. **Динамическая координация relay↔exit (SSH с релея)** — отклонено: нарушает
   границу доверия и хрупка во время блокировки (2PC по деградирующему каналу).
2. **nft-фильтр по src на общем 51825 без `awg2`** — отклонено: не изолирует
   клиентские пиры, нельзя безопасно крутить порты, хуже откат.
3. **Закрыть P25 как «won't do»** — отклонено: длинные эпизоды (до 5 ч) реальны,
   но статистику уже пересчитали (медиана 7 мин).
4. **Автомат на `handshake_age`** — отклонено по данным WP-M0 (ложные срабатывания).

## Последствия

- `+` клиентские пиры не затрагиваются; порт ноги изолирован; манёвр ~5–15 с;
  откат локальный; границу доверия не двигаем.
- `−` новый интерфейс/юниты и пул правил на exit; alert-watch должен читать
  пульс с настраиваемого интерфейса (`ALERT_RELAY_IFACE`, default `awg0`);
  нужен ADR/SPEC-sync в доках.
- Риск: смена порта не помогает, если режется весь UDP до IP — тогда IPv6-нога
  или TCP-Reality (проверяется в живом окне).

## Проверка (AC)

- P24: клиентские пиры живы; `awg2` принимает только `<relay-ip>`; внешний скан
  портов пула — тишина/без ICMP; переживает reboot; alert-watch читает `awg2`.
- P25: `nft drop` активного порта пула → восстановление liveness < 60 с,
  policy-routing цел, повтор блокируется cooldown'ом, откат при отказе всех портов.
