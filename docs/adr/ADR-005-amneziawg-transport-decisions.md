# ADR-005: AmneziaWG — источник пакетов, порт, клиентский режим, линия версий, PSK

- **Дата:** 2026-11-10
- **Статус:** accepted
- **Контекст SPEC:** [SPEC-20261110-amneziawg-transport](../team/specs/SPEC-20261110-amneziawg-transport.md)
- **Закрывает:** OQ-1..OQ-6 из [REQ-20261110-amneziawg-transport](../team/requirements/REQ-20261110-amneziawg-transport.md)

## Контекст

Живой asv1: Reality (TCP 443), Hysteria2 (UDP 443), XHTTP (TCP 8443, за
SNI-фолбэком). Нужен четвёртый, независимый UDP-транспорт AmneziaWG
(обфусцированный WireGuard) как резерв, когда TCP/QUIC-каналы детектированы.
Факты REQ: у `amneziawg-go` нет GitHub releases; WG-класс — tun + root;
конфиг WG-совместимый + параметры обфускации Jc/Jmin/Jmax/S1–S4/H1–H4.

## Решения (по OQ)

### OQ-3 — источник: PPA `ppa:amnezia/ppa` (apt), kernel-модуль

| Вариант | Плюсы | Минусы |
|---|---|---|
| **PPA `ppa:amnezia/ppa` → `amneziawg-tools` + `amneziawg-dkms`** (выбран) | официальный источник Amnezia; поддержка Ubuntu 24.04 (kernel 6.8 ≥ 6.7); никакого Go-тулчейна; GPG-подпись apt = целостность из коробки; обновления через apt | mirror-конвенция VDS_GITHUB_MIRROR не применима (Launchpad ≠ github-release); DKMS-сборка модуля при апдейте ядра |
| Сборка amneziawg-go из исходников | точный pin версии | нужен Go-тулчейн на сервере — против минимализма; VDS_GITHUB_MIRROR (gh-proxy префикс) **не применим к git clone/make** — при резке github установка не гарантирована |
| Статический бинарь из чужих релизов | нет тулчейна | нет официального upstream-истца (релизов нет); недоверенные сторонние бинари = supply-chain-риск |

- Установка: `add-apt-repository ppa:amnezia/ppa` → `apt-get install amneziawg-tools amneziawg-dkms`
  → `apt-mark hold amneziawg-tools amneziawg-dkms` (pin), версия фиксируется в
  `state.protocols["amneziawg"]`. Проверка целостности — подпись apt (отклонение от
  паттерна «pin+SHA256» Xray/Hysteria2 оправдано: пакеты подписаны GPG репозитория).
- **Mirror:** `VDS_GITHUB_MIRROR` для AWG-пути не используется и кодом не читается;
  отклонение от NFR «mirror» задокументировано здесь как осознанное (источник —
  Launchpad, не github). Если PPA/launchpad недоступен с сервера — E1: читаемый
  отказ до изменений; ручной fallback (`apt download` на другой машине + перенос
  .deb) описан в SPEC §5, автоматизации нет.
- **Fallback при провале DKMS** (нет headers/сборка падает): userspace
  `amneziawg-go` (сборка из исходников) — **не реализуется в v1**, только как
  документированный путь эскалации к архитектору.

### OQ-5 — kernel-модуль (следствие OQ-3)

Выбран kernel-модуль `amneziawg-dkms`: производительность выше userspace, не
требует Go, интерфейс — обычный netdev `awg0` (виден в `ip link`/`awg show`).
Юнит: `vds-amneziawg.service` из `systemd/vds-amneziawg.service.tpl`,
`ExecStart=awg-quick up /etc/amnezia/awg0.conf`.

### OQ-1 — порт: UDP 51825 (фиксированный дефолт + проверка)

| Вариант | Оценка |
|---|---|
| 51820 (дефолт WG) | отклонён — самый сканируемый/детектируемый порт WireGuard |
| UDP 443 | отклонён — занят Hysteria2, и смешение UDP-профилей снижает устойчивость |
| **51825 (фикс. дефолт, `--port` переопределяет)** | высок, немнемоничен семейству 5182*, не в списке типичных блокировок; проверка `ss -ulnp` ДО изменений (E3) |

Порт фиксируется в `gateway/paths.py` (`AWG_PORT_DEFAULT = 51825`) и в state.

### OQ-2 — клиентский режим: вариант (b) — «conf-файл + AmneziaVPN»

Подтверждена склонность владельца. vpn-manager — user-level socks-раннер;
AWG требует tun + root — тащить sudo/systemd-user-политики в менеджер ради
одного протокола — непропорциональное усложнение. v1: сервер выдаёт клиентский
`.conf` (0600), хранение профиля в vpn-manager опционально, подключение —
через AmneziaVPN-приложение. Root-раннер (a) — отдельная будущая фаза с
собственным REQ/ADR (pkexec/sudoers — необратимая по духу политика).

### OQ-4 — линия версий: AWG 1.5-набор параметров (Jc, Jmin, Jmax, S1, S2, H1–H4 фиксированные)

- Генерируем **только 1.5-параметры**: `H1–H4` — одиночные uint32 (попарно
  различимые), `S1/S2` — паддинги, `S3/S4`, диапазонные `H`, `HeaderProtectionKey`
  (AWG 2.0/3+) **не используем**.
- Обоснование: старые AmneziaVPN-клиенты понимают только 1.5-набор; новые
  приложения обратно совместимы с 1.5-профилями. Сервер на актуальной версии
  из PPA с 1.5-параметрами работает с 1.5-клиентом. Обфускация (junk+padding+
  подмена заголовков) при этом полностью активна — цель фазы 4 выполняется.
- **Верифицируемый гейт:** WP-6 приёмка — импорт сгенерированного .conf в
  AmneziaVPN владельца. Если приложение отвергает формат → стоп, ADR-005
  правится на 2.0-набор (S1–S4 ≥ 12, H-диапазоны), SPEC обновляется — не «чиним
  на ходу».

### OQ-6 — PSK: включён по умолчанию

Каждый клиент получает `PresharedKey` (`awg genpsk`), хранится в state.json
(0600) и в клиентском .conf; opt-out `--no-psk` для отладки. AmneziaVPN
импортирует PresharedKey штатно (WG-совместимая секция). PSK добавляет защиту
от passive-компромисса статических ключей — стоимость нулевая.

## Последствия

- Положительные: никакого тулчейна на сервере; официальный подписанный источник;
  независимость от github; клиент — без root-инфраструктуры в vpn-manager.
- Отрицательные / долг: DKMS-зависимость (пересборка модуля при апдейте ядра —
  контролировать при sysinfo/ручной приёмке); mirror-конвенция на этот
  транспорт не распространяется (задокументировано); владельческий гейт на
  импорт .conf в его AmneziaVPN (OQ-4) — единственная точка, где ADR может
  потребовать поправки.
- Трудно изменить позже: UDP-порт 51825, имя интерфейса `awg0`, пути
  `/etc/amnezia/awg0.conf`, юнит `vds-amneziawg.service` — локализованы в
  `gateway/paths.py`; смена — только новый ADR.

## Как откатить

1. `vds amneziawg remove --apply` (dry-run по умолчанию): стоп/disable юнита,
   удаление `/etc/amnezia/awg0.conf` (после бэкапа) и клиентских .conf, вычистка
   AWG-клиентов из state.json (бэкап state перед мутацией).
2. Пакеты: `apt-mark unhold …` → `apt-get purge amneziawg-tools amneziawg-dkms`;
   PPA можно оставить (пассивный) или `add-apt-repository --remove ppa:amnezia/ppa`.
3. UFW: правило `allow 51825/udp` удалить вручную (правила UFW из этого цикла —
   только это одно; остальные не трогаем).
4. Reality/XHTTP/Hysteria2 не затрагиваются ни на одном шаге (инвариант REQ §4).
